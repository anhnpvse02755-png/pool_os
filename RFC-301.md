# RFC-301 — Recording Pipeline

**Version:** 1.0
**Status:** APPROVED FOR IMPLEMENTATION
**Priority:** P0
**Owner:** Claude Code

## Goal

Rebuild the entire Recording Pipeline — NOT patch individual screens, but make the whole business workflow run exactly as designed.

After RFC-301, every training activity must produce complete, durable, queryable data. This is the foundation of all of Pool OS.

Correct workflow:

```
Player → Session → Practice/Match → Rack → Shot → Event → Database → Statistics → Coach → Dashboard
```

---

## Scope

**ONLY the Recording Pipeline may be changed.** Everything else is read-only.

**Included:**

- Session, Match, Practice, Rack, Shot, Event
- Repositories, Providers
- Database persistence, Transactions
- Navigation related to recording
- Summary generation

**NOT included:**

- Coach, Statistics calculation, Dashboard, Equipment snapshot, Readiness
- Theme, Localization, Settings, Recommendation, AI

---

## 7 Business Rules

1. **Session owns everything** (Session → Match → Rack → Shot → Event). Nothing exists outside a Session.
2. **A Shot MUST belong to exactly one Rack** — no `rackId` null / 0 / missing Rack.
3. **An Event MUST belong to exactly one Shot** — no `shotId` null / 0.
4. **Practice uses EXACTLY the same pipeline as Match**; only scoring differs. Practice is NOT special.
5. **Every action persists IMMEDIATELY** (add Shot → Database, do NOT hold in memory and save later).
6. **Finish Session closes everything:** Finish Match → Finish Rack → flush data → generate summary → Statistics ready.
7. **Nothing may disappear after restart** — every Session/Match/Rack/Shot/Event survives.

---

## Technical Requirements

- **SessionRepository = Aggregate Root.** No provider manipulates Match state directly — everything goes through Session.
- **Match:** support ANY race (3/5/7/9/11/13/15/21/custom int); remove hardcoded Race 5/7. Winner: `playerScore >= raceTo` (NOT `== raceTo`).
- **Rack:** stores winner, break player, runout, safety count, position quality, notes — NOT hidden in a JSON blob if the schema supports it; if the schema cannot change, centralize serialization, no duplicated JSON parsing.
- **Shot:** `rackId`, timestamp, cue, shotType, difficulty, result, positionScore, spin, english, distance, notes; Repository must reject invalid `rackId`.
- **Event:** `shotId`, eventType, severity, notes, timestamp; Repository must reject invalid `shotId`.
- **Persistence:** Repository is the ONLY persistence layer; Provider NEVER writes Drift directly; no memory-only objects.
- **Transactions:** creating Match → Rack → Shot → Event must be transaction-safe, no partial write.
- **Navigation:** Match → Summary → Back to Session; no grey screen, no stuck loading, no mixing Navigator/GoRouter.
- **UI Session Screen:** when `activeMatch == null` hide Win/Lose/Shot/Event/Drill buttons; when Match active show them; when Finish Match the buttons disappear. **Practice Screen:** must create a Rack before a Shot.
