# FEATURE_009 — Player Timeline & Activity Feed

## Goal

Provide a deterministic, chronological timeline of a player's activity by composing existing recorded facts from Match, Training, Equipment snapshots, Player Model projections, and Knowledge Mastery evidence.

The timeline is a read-only projection. It never creates inferred history or synthetic events.

---

## User Value

The player can answer:

- What have I done recently?
- Which cue did I use?
- When did my Player Model update?
- When did I complete training?
- What knowledge did I master recently?

This becomes the primary historical activity feed for Player Profile and future Coach review.

---

## Ownership

Timeline owns:

- Activity projection
- Activity ordering
- Timeline rendering
- Timeline filtering

Timeline does NOT own:

- Match
- Training
- Equipment
- Player Model
- Knowledge
- Coach
- Analytics

Each source remains authoritative.

---

## Inputs

Only existing accepted sources may be consumed.

### Match

Completed Match

Required fields:

- Match ID
- Finished timestamp
- Match result
- Equipment snapshot

---

### Training

Completed Training

Required fields:

- Training ID
- Finished timestamp
- Equipment snapshot

---

### Equipment

EquipmentPerformanceProjection

May expose:

- equipmentId
- lastUsed

No EquipmentChanged event exists.

---

### Player

PlayerModelProjection

May expose:

- projection digest
- lastUpdated

Only the latest projection exists.

Emit a snapshot activity only.

Never emit "Player improved".

---

### Knowledge

Mastery evidence

Only if a real timestamp exists.

---

## Outputs

Immutable

PlayerTimelineEntry

Fields:

- id
- sourceType
- sourceId
- occurredAt
- title
- subtitle
- icon
- navigationTarget
- sourceDigest

No mutable state.

No ranking.

No recommendation.

---

## Ordering

Newest first.

Tie-breaking:

1. occurredAt DESC
2. sourceType
3. sourceId

Ordering must be deterministic.

---

## Navigation

Entries open existing screens only.

Match
→ Match Detail

Training
→ Training Detail

Knowledge
→ Knowledge Detail

Player Model
→ Player Profile

Equipment
→ Equipment Detail

No new navigation system.

## Prohibitions

Do NOT:

- invent events
- infer milestones
- infer cue changes
- infer Player improvement
- infer important matches
- generate AI summaries
- create Analytics timeline
- duplicate source repositories
- duplicate Match/Training history

Timeline must be replayable entirely from existing facts.

---

## Acceptance Criteria

Engineering must demonstrate:

1.

Timeline contains:

- completed Match
- completed Training
- Player Model snapshot
- Knowledge Mastery update
- Equipment lastUsed

when corresponding source facts exist.

2.

Deleting the projection cache and rebuilding produces byte-identical JSON.

3.

Ordering is deterministic across rebuilds.

4.

Changing Active Cue after a Match never changes historical timeline entries.

5.

Every entry navigates to an existing screen.

6.

No duplicate entries are produced from one source fact.

7.

No source fact is modified.
